一、项目概述
1.1 背景说明
本需求基于已有 Java 商城系统做二次开发。商城基础功能（用户体系、商品、订单、支付、优惠券、基础分销）均已具备，本次仅需新增 2+1 链动裂变分销模块。本文档仅描述增量部分。
1.2 模式核心规则
2+1 链动模式的核心机制如下：
代理：用户购买指定「代理礼包」后成为代理，获得推荐资格与直推分佣权。
老板：代理直推满 2 名有效代理（完成购买）后，自动晋升为老板，解锁团队分佣。
2（晋升条件）：直推满 2 个有效代理。
1（留人机制）：晋升老板后，第 3 个及之后的直推下线触发「留 1 / 滑落」规则。
滑落：上级团队已满时，新用户自动滑落至下级团队的空位，保证团队均衡发展。
帮扶：老板需扶持被「留 1」的下线也晋升为老板，完成后获得帮扶奖励。

三、核心业务流程
3.1 用户升级流程
游客 → 购买代理礼包 → 成为【代理】
代理 → 直推第 1 人 → 仍为代理
代理 → 直推第 2 人 → 自动晋升【老板】
老板 → 第 3 人起 → 触发「留 1 / 滑落」规则
3.2 分佣触发流程
用户 C 购买礼包
→ 直推人 A 获得【直推奖】
→ A 的上级老板 B 获得【见单奖】
→ 若 B 与 A 平级（同为老板），B 获得【平级奖】
→ 若涉及帮扶关系，帮扶人获得【帮扶奖】
3.3 滑落规则
新用户通过分享链接 / 海报二维码进入
→ 判断分享人身份与团队容量
→ 若分享人为老板且团队未满 → 进入其团队
→ 若分享人团队已满 → 按预设规则向下滑落至最近空位
→ 滑落路径全程记录，可追溯

6.2 上下级关系链
绑定上级：新用户通过分享链接 / 海报扫码进入，自动绑定上级。
关系锁定：绑定后不可自行更改，仅后台可干预。
层级限制：默认最多 3 代见单奖，可配置。
团队树查询：返回指定用户 N 代下线结构。
关系变更：仅后台可操作，记录审计日志。
6.3 分佣计算引擎（核心）
调用入口：订单触发分佣事件时（支付完成 或 订单完成，可配置），通过 MQ 异步消费。
分佣顺序：
步骤 1：直推奖：直接上级为有效代理时发放。
步骤 2：见单奖：向上追溯 N 代老板（N 可配），逐代发放。
步骤 3：平级奖：下级与上级同为老板时，给上级发放。
步骤 4：帮扶奖：异步检测帮扶完成，独立发放。
关键约束：
幂等：基于 order_id + reward_type 建唯一索引，防止重复发放。
冻结期：佣金发放后进入冻结状态，T+N 天后才可提现（N 可配，默认 1）。
退款失效：退款审核通过后，对应订单产生的佣金标记为「失效」，已提现的需逆向追回。
事务：关系变更 + 身份变更 + 佣金发放在同一事务中。

6.5 帮扶机制
留 1 指定：老板晋升时，系统自动将第 3 个及之后的直推下线标记为「帮扶对象」。
帮扶完成检测：帮扶对象晋升为老板时，触发帮扶完成判定。
帮扶奖励：完成后给帮扶人发放一次性奖励（金额后台可配）。
超时机制（可选）：帮扶超过 N 天未完成，帮扶对象自动释放。
6.6 后台管理（新增菜单）
链动数据看板：代理数、老板数、今日新增、佣金发放总额、团队层级分布。
奖励规则配置：直推 / 见单 / 平级 / 帮扶各奖项金额与比例，表单可编辑。
分佣触发配置：选择支付完成或订单完成触发，随时可切换。
冻结期配置：设置 T+N 冻结天数。
用户链动管理：查看任意用户身份、上级、团队树，手动调整关系。
佣金明细：按用户 / 类型 / 时间筛选，支持导出 Excel。
滑落日志：查看所有滑落记录，可追溯。
关系审计日志：所有关系变更的操作用户、前后值、原因。
6.7 前端增量（H5 / 小程序）
我的身份页：当前身份、直推进度（2/2）、距离老板还差几人。
我的团队：树状图展示（默认 2-3 层），点击展开。
推广中心：生成专属海报（含二维码）、复制邀请链接。
收益明细：分类型展示（直推 / 见单 / 平级 / 帮扶），汇总统计。
链动规则说明：模式规则图文说明页。

九、技术约束与注意事项
幂等：分佣计算接口必须支持幂等（order_id + reward_type 唯一索引）。
事务：关系变更 + 身份变更 + 佣金发放在同一事务中。
异步：分佣计算走消息队列（如 RocketMQ / Kafka），避免阻塞主流程。
防刷：同一设备 / 同一支付账号 / 同一 IP 短时间大量下单需风控拦截。
死循环保护：关系链查询必须设最大深度限制，防止数据异常导致无限递归。
配置热更新：奖励规则 / 触发时机 / 冻结期变更后无需重启，即时生效。
佣金冻结：冻结期内佣金不可提现，到期自动转为可提现状态。
退款失效：退款触发后，对应佣金置为失效，已提现部分进入待追回队列。
